# Task Log: Modeling Data Prep (master feature table + EDA + LME/LightGBM prep)
_Last updated: 2026-09-09_

## Scope
Build the final modeling-ready datasets for the Delhi Phase 1 pilot: join every processed covariate table (CPCB PM2.5 target, MAIAC/MERRA2 gap-filled AOD, ERA5-Land met, ERA5-BLH, NDVI, WorldCover land-use, SRTM terrain, OSM road/industrial/powerplant covariates) into one master feature table, run a reusable 7-phase EDA on it, then produce two model-specific prepared datasets -- one for the fixed LME equation (random intercept by station, AOD x season interaction), one for a LightGBM comparison model -- with the EDA findings feeding concrete decisions in both.

## Completed

### 1. Master feature table (2026-09-09)
- `scripts/modeling/dataset_prep/01_build_master_table.py`: starts from `pm25_daily_final.csv` (13,641 station-days, 42 stations) and left-joins everything else onto it. Canonical station name/lat/lon comes from `cpcb_stations_delhi_status.csv` filtered to `status == 'KEEP'`, not from any of the covariate tables (several of which carry their own copies).
- Time-varying joins on `[location_id, date]`: AOD gapfilled (renaming its `gap_filled` -> `aod_gap_filled` to avoid a name clash with NDVI's own `gap_filled` column), ERA5-Land (dropping `dewpoint_c` -- redundant with `relative_humidity`, an explicit earlier decision; renaming `n_hours_used` -> `n_hours_met`), ERA5-BLH (renaming `n_hours_used` -> `n_hours_blh`).
- NDVI is 5-day composites, not daily, so it needed a period-range join instead of a direct date match: `pd.merge_asof(direction="backward", by="location_id")` matching each station-day to the period whose `period_start` is the closest one at-or-before that date, then verifying every matched date actually falls at-or-before `period_end` too (0 rows failed this check across all 13,641 rows). Its own `gap_filled` column renamed to `ndvi_gap_filled`.
- Static per-station joins on `location_id` alone: WorldCover (all 11 land-use % columns kept in the master table -- reduction happens downstream, differently per model), SRTM terrain, OSM road density/industrial fraction/powerplant distance.
- Master table: 13,641 rows x 42 columns. Missing-value check: `aod_055` missing for 101 rows (station-days where both MAIAC and MERRA2 were unavailable, and which also happened to have a valid PM2.5 reading -- a subset of the 113 fully-unfillable station-days in the full AOD calendar grid), `confidence_rmse` missing for 7,093 rows (these are the *observed*, non-gap-filled AOD rows, where confidence doesn't apply), `nearest_powerplant_name` missing for 10,007 rows (informational only, not a feature).

### 2. EDA (2026-09-09)
- `notebooks/01_eda_master_feature_table.ipynb`: a reusable 7-phase EDA template (structural, data quality, univariate, target-specific, bivariate, multivariate/correlation, group/time/space structure), built config-driven (`DATA_PATH`/`TARGET_COL`/`GROUP_COL`/etc. at the top) so it can be reused for other datasets, plus two follow-up sections specific to this decision:
  - **Section 8** reruns VIF on the *actual* final LME design matrix (not the master table's full 11-column WorldCover set), to check whether dropping 5 columns actually fixed the compositional-data closure problem found in Phase 6.
  - **Section 9** fits a real `MixedLM` (the actual M0 fixed effects, random intercept by `location_id`) on both a raw-`pm25_daily` and `log(pm25_daily)` candidate dataset, and compares residual skew and residual variance-by-fitted-quintile -- the real basis for the target-transform decision below.
- **Target distribution**: `pm25_daily` heavily right-skewed (skew 1.89, kurtosis 4.67; D'Agostino test rejects normality decisively). `log(pm25_daily)` skew -0.41 -- much closer to symmetric, but this alone wasn't taken as sufficient evidence (see Section 9 below).
- **Data quality issues found** (not caught earlier in the pipeline): 46 station-days with `pm25_daily` exactly 0.0 (physically implausible, likely sensor artifacts -- also breaks a log transform outright); 11 station-days with negative `aod_055`, all MERRA2-calibrated gap-fills from Aug 19-21 2025 (monsoon washout) -- the calibration model has no positivity constraint, so very clean-air days can dip slightly below zero.
- **Multicollinearity**: `wetland_herbaceous_pct` <-> `water_pct` (r=0.975, both already excluded from the LME feature set). `boundary_layer_height` <-> `temperature_c` (r=0.76, both required by the fixed M0 equation, kept as a reported interpretation caveat). The 11 raw WorldCover `_pct` columns showed near-infinite VIF in Phase 6 (compositional-data closure problem, confirmed not assumed) -- Section 8 found the fix (dropping `water_pct` as reference) only **partly** worked: the exact singularity is gone, but `built_up_pct` (160), `tree_cover_pct` (96), and `cropland_pct` (65) remain well above the usual VIF>5-10 danger threshold, since together they're ~93% of the average station's land-use composition and still substantially trade off against each other even with one reference category removed.
  - **Decision**: leave the 6 LME land-use columns as individual categories rather than grouping them further. Grouping would erase the ability to separate `cropland_pct`'s effect, which matters scientifically for Delhi's crop-burning-driven PM2.5 spikes. Elevated VIF widens the *precision* of individual coefficient estimates (wider standard errors) but doesn't invalidate the model -- a reportable, standard limitation in LUR/PM2.5 literature, not a reason to sacrifice interpretability.
- **Station structure**: rough ICC (between-station variance share) is low, ~2.3% -- doesn't invalidate the random intercept, reported candidly as a limitation.
- **Section 9 (residual diagnostics, the actual target-transform decision)**: fitting the real M0 fixed effects with a random intercept per station on both targets showed residual skew is a wash (raw 1.68 vs log -1.59, just flipped sign) -- but residual variance across fitted-value quintiles is decisive: raw-scale residual variance grows **~12.8x** from the calmest to the most polluted fitted values (severe heteroscedasticity, a real violation of the constant-variance assumption LME needs for valid standard errors/p-values), while log-scale residual variance stays flat (~0.2-0.36) across the whole range. Heteroscedasticity is the more damaging violation at this sample size (n=13k+), so **log wins on the assumption that actually matters**, not on raw-target skew alone. One caveat carried forward, not resolved: log residual kurtosis is *higher* than raw (9.2 -> 19.8, heavier tails), likely a handful of very-low-PM2.5 days behaving oddly once log-compressed -- worth a look during actual model diagnostics.

### 3. LME-ready dataset (2026-09-09, finalized after EDA)
- `scripts/modeling/dataset_prep/02_prepare_lme_dataset.py`. Gated behind a `NOT_SET` guard on `target_transform` (same pattern as `maiac_gapfill/04_score_confidence.py`): the stage hard-fails via `raise SystemExit` until `modeling.lme_prep.target_transform` in `params.yaml` (and the matching `--target_transform` value in `dvc.yaml`'s `cmd`) is set to `"raw"` or `"log"` by hand, forcing the EDA notebook to actually be reviewed first. `dvc.yaml`'s stage now also depends on `notebooks/01_eda_master_feature_table.ipynb`, so a notebook change marks the stage dirty.
- Drops the 46 `pm25_daily <= 0` rows and clips the 11 negative `aod_055` values to 0 (both toggleable via `--drop_zero_target_rows`/`--clip_negative_aod_to_zero`, defaulting to true, applied before the complete-case filter and before scaling).
- Complete-case filter: drops any row with a NaN in a model column -- in practice only `aod_055` ever triggers this. 13,595 -> 13,494 rows.
- WorldCover reduced to 6 columns: dropped `snow_ice_pct`/`mangroves_pct`/`moss_lichen_pct` (literally 0% at all 42 Delhi stations), `wetland_herbaceous_pct` (nonzero at only 3 of 42 stations, negligible), and `water_pct` as the reference category (resolves the compositional-data closure problem's exact singularity). Kept: `tree_cover_pct, shrubland_pct, grassland_pct, cropland_pct, built_up_pct, bare_sparse_veg_pct` (left as individual columns, not further grouped -- see EDA decision above).
- `target_transform` set to **`log`** (confirmed via Section 9's residual diagnostics, not raw skew alone): a new `modeling_target` column = `log(pm25_daily)` is added (with a hard-fail safety check if any non-positive `pm25_daily` values remain), while the raw `pm25_daily` column is kept in the output for reference and back-transformation.
- Every continuous regressor (AOD, met, NDVI, terrain, OSM, the 6 kept land-use columns) is z-scored; scaling stats written to a companion `lme_scaling_params.csv`. Season dummies use `summer` as reference; AOD x season interaction columns built from the *scaled* AOD.
- `confidence_bucket` kept in the output as metadata only -- not a regressor, reserved for a future sensitivity refit excluding low-confidence filled AOD days.
- **Final result**: 13,494 rows x 30 columns. Rows per season: summer 3,471 / monsoon 4,586 / post_monsoon 2,371 / winter 3,066, all 42 stations represented in every season. Rows per `confidence_bucket`: observed 6,985 / medium 3,160 / high 2,137 / low 1,212.

### 4. LightGBM-ready dataset (2026-09-09, finalized after EDA)
- `scripts/modeling/dataset_prep/03_prepare_lightgbm_dataset.py`. Applies the same two EDA-driven data-quality fixes as the LME dataset (`--drop_zero_target_rows`/`--clip_negative_aod_to_zero`, default true, no `NOT_SET` gate needed here) -- a wrong `pm25_daily==0` label or an impossible negative `aod_055` reading is wrong regardless of which model consumes it. No `target_transform` option: tree splits are invariant to any monotonic transform of the target, so `log(pm25_daily)` would not change LightGBM's learned structure, only complicate reporting.
- No complete-case filtering beyond the zero-target drop -- native NaNs preserved (101 rows with NaN `aod_055`, 7,086 with NaN `confidence_rmse`, both counts shifted slightly down from the pre-fix 13,641-row version since the 46-row drop removed a handful of overlapping rows).
- WorldCover reduced to 8 columns (only the 3 always-zero columns dropped) -- deliberately *not* matched to LME's 6, since `water_pct`/`wetland_herbaceous_pct` carry real station-to-station variation and trees pay no collinearity cost for keeping them.
- `confidence_rmse`, `aod_gap_filled`, `ndvi_gap_filled` kept as informative features. `location_id` kept as an ID/grouping column only (documented as excluded from the training feature list). `season` kept as a plain string (documented to cast to category dtype at training time).
- **Final result**: 13,595 rows (down from 13,641 pre-EDA-fix) x 27 columns. Rows per season: monsoon 4,687 / summer 3,471 / winter 3,066 / post_monsoon 2,371.

## Key decisions
- **2026-09-09** -- WorldCover collinearity handled differently per model, not with one shared reduced set: LME drops to 6 columns (reference-category drop, keeping fine-grained land-use types rather than combining into broad groups -- standard practice in PM2.5/LUR literature since built-up vs. tree-cover vs. cropland carry distinct physical meaning). LightGBM keeps 8 columns, since collinearity isn't a cost for tree models and `water_pct` has genuine signal worth keeping.
- **2026-09-09** -- Confidence/gap-fill metadata (`confidence_bucket`) stays out of the base LME regression entirely -- kept as a non-regressor column for a later, separate sensitivity-analysis refit, not fit directly.
- **2026-09-09** -- The 113 unfillable AOD station-days are not special-cased: LME drops them via ordinary complete-case filtering, LightGBM keeps them with native NaN in `aod_055`.
- **2026-09-09** -- AOD x season interaction columns are built from the *scaled* AOD value, not the raw value -- caught as a bug during verification and fixed by reordering scale-then-interact.
- **2026-09-09 (post-EDA)** -- `target_transform = log` for the LME dataset, decided from residual diagnostics on an actual fitted MixedLM (Section 9 of the EDA notebook), not from the raw target's skew alone: raw-scale residual variance blows up ~12.8x from low to high fitted values (severe heteroscedasticity), log-scale stays flat (~0.2-0.36). A `NOT_SET` guard (mirroring `maiac_gapfill/04_score_confidence.py`) enforced that this decision could only be made after the EDA notebook was actually reviewed, not left at a default.
- **2026-09-09 (post-EDA)** -- Leave the 6 LME land-use columns as individual categories despite elevated VIF on 3 of them (`built_up_pct`=160, `tree_cover_pct`=96, `cropland_pct`=65), rather than grouping into fewer, less-correlated categories. Grouping would lose the ability to isolate `cropland_pct`'s effect (important for Delhi's crop-burning PM2.5 spikes); elevated VIF widens coefficient standard errors but doesn't invalidate the model, and is reported as a known limitation instead.
- **2026-09-09 (post-EDA)** -- The 46 zero-`pm25_daily` rows and 11 negative-`aod_055` rows found by EDA are data-quality fixes applied to **both** prepared datasets (LME and LightGBM), not just LME -- these are wrong labels/impossible readings independent of model type, unlike the log-transform decision, which is LME-specific (LightGBM ignores it, since tree splits are invariant to monotonic target transforms).

## Data notes & gotchas
- NDVI's period-range join uses `pd.merge_asof`, which requires the "on" column (`date`/`period_start`) sorted *globally*, not just within each `by` group -- sort by `date`/`period_start` alone, let `by=` handle the station matching, then re-sort the output back to `[location_id, date]` order afterward.
- `master_feature_table.csv` is a deliberate superset -- it keeps metadata columns that aren't features in either prepared dataset, so nothing is lost if a different reduction is wanted later without re-running the full join.
- `dvc`, `nbformat`, `nbconvert`, `statsmodels` needed reinstalling this session (same non-persistence noted in every prior session's log); `pandas`/`yaml`/`numpy`/`matplotlib`/`seaborn` did persist.
- `dvc repro` removes a stage's tracked outputs from disk *before* running the stage's command -- if the command then fails (e.g. the `NOT_SET` gate firing on purpose, to test it), the tracked output files are left deleted even though nothing in git changed. Recovered with `dvc checkout <path>` (restores from the DVC cache) rather than needing to re-run the stage for real.
- Hit stale `.git/index.lock` and `.git/HEAD.lock` files mid-session (from an earlier interrupted git operation) that blocked `git add`/`git commit` with "Operation not permitted" -- resolved by requesting delete permission on the repo folder (`device_request_delete_permission`) and removing the lock files directly; commits succeeded immediately after.
