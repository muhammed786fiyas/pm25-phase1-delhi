## Blockers

- **The DVC remote is a folder on this laptop.** `.dvc/config` is committed pointing at `E:\PROJECTS\MAIN PROJECTS\INTERNSHIP\CODEBASE`. `dvc push` succeeds, but the data never leaves this drive, and anyone else cloning gets a path that doesn't exist for them. Delhi reproduces here; not yet elsewhere. Needs a shared remote (Google Drive, S3 or a network folder) -- a decision about where the project's data should live.

## Gotcha

An `mlflow ui` command written into the README from memory would have failed: MLflow 3 refuses the file-based store in the UI too, not just in scripts, unless `MLFLOW_ALLOW_FILE_STORE=true` is set. Caught by testing it before committing. Worth testing every command that goes into documentation.
