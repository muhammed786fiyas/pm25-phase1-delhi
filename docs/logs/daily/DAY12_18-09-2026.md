## Key decisions

- **Publication threshold, pre-registered before any other city runs**: publish LightGBM only if it beats the LME on spatial-LOSO R2 in raw ug/m3 for that city; otherwise publish the LME. Absolute floor R2 > 0. Chosen relative rather than absolute because it needs no advance knowledge of a city and self-calibrates to its difficulty. The floor is not vacuous -- Delhi's log-fit LME scored on raw fails it at -0.226. Do **not** benchmark against literature R2: those are almost always random CV, not spatial LOSO.
- **Both LME fits for every city** -- log for the coefficient table (the only valid p-values), raw as the fair comparator against LightGBM.
- **Acceptance test for the roster rewrite: Delhi must regenerate its exact 42 KEEP stations.** Met.
- **Delhi keeps every stage.** Nothing deleted or split into a separate pipeline file, so `delhi-phase1-complete` stays fully reproducible. Other cities will run a reduced set (raw + log LME, LightGBM), keeping `*_gapfill_robustness` and `diagnose_lightgbm_aod_coupling` per-city.
- **External-service stages are frozen snapshots**, not re-fetched on every repro -- OpenAQ and Earth Engine can revise historical data, so the snapshot is what makes results reproducible. Unfreeze deliberately for a refresh or a new city.
- **The hardcoded `drop_stations` list is deleted.** The four stations it named all fail the existing 60% completeness threshold, so a rule that transfers to any city now drops them.

## Results

**The roster rules reproduce the hand-curated roster exactly.** 47 eligible == the 47 stations actually downloaded; 42 rule-based KEEP == the 42 hand-curated KEEP, identical sets, identical coordinates. Margins are wide: the five completeness drops sit at 12.6-44.1% against a 60% threshold, while every KEEP station is at 72.9% or above.

Notably, the four stations previously hardcoded as `DROP_qc_failed` are explained by completeness alone. Their stuck-sensor and zero-value rates were corroborating, not decisive -- 10820 has only 1.0% zeros and 1.6% stuck hours, cleaner than several KEEP stations, and was always a completeness drop.

**The finding that reshapes the multi-city plan:** Chennai (~9 alive stations) and Kolkata (~13) are far sparser than Delhi (49) and Mumbai (41). Block-nested Optuna tuning is impossible at that n, and small-n fragility is roughly 5x Delhi's -- where a single station once swung pooled raw R2 from +0.515 to -0.226. Widening Chennai's bbox changes nothing (11 either way); the CPCB network there is genuinely that sparse.

## Blockers

None outstanding. Two things cost time and are worth remembering:

- **The environment starts bare every session.** The first full repro stopped at stage 12 on a missing `geopandas`. Installing all of `requirements.txt` up front and checking every third-party import beforehand avoids discovering the next missing package an hour in. `earthengine-api` and `pytz` are needed but not obviously so.
- **pandas 3 changed missing-value comparison**: `astype(str)` no longer makes two missing values compare equal, which made a verification script report 10,007 false differences. Fill missing values before comparing text columns.
