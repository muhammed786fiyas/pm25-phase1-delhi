**Per-row out-of-fold predictions** (step 2). `02_validate_lightgbm_cv.py` was computing
13,595 honest out-of-sample predictions every run and discarding them, keeping only
aggregates. Now written to `reports/lightgbm/primary/cv_spatial_loso_oof_predictions.csv`
with fold id, observed, predicted and residual. Worth keeping independent of the app —
they are a reusable calibration set, and they are what lets the station download ship an
out-of-sample estimate instead of an in-sample fit.

**Conformal prediction intervals** (steps 3–4). New
`scripts/modeling/lightgbm/04_calibrate_conformal_intervals.py`, wired as a DVC stage.
Normalized conformal scaled by the prediction: `interval = prediction × (1 ± q)`, q a
percentile of the relative absolute residual on out-of-fold rows. **q = 0.5514 at 90%**
(±55.1% of the estimate); held-out coverage **89.9%** against a 90% target, measured by
calibrating on 41 stations and testing on the 42nd. 80% and 95% are calibrated too and
sit in the JSON. API and UI now serve the interval.

**Station data download** (step 5). `/api/download/stations` plus `/preview` and
`/columns`, and a download panel in the UI with a checkbox grid for feature selection and
a live row/column/size preview. ZIP by default, bundling parquet + CSV +
`DATA_DICTIONARY.txt` + `ATTRIBUTION.txt`; raw `parquet` and `csv` also available for
anyone scripting against it. 13,595 rows × 32 columns, 0.59 MB as parquet.

Each row carries **measured** PM2.5 beside the **out-of-sample** prediction and its
interval, joined from the OOF file. Verified on the delivered file rather than assumed:
RMSE 33.73 µg/m³, exactly the published spatial-LOSO figure, and interval coverage 90.0%
against the 89.9% the calibration predicted. An in-sample fit would have scored far better
and been worth far less.

## Key decisions

- **The distance-based confidence badge is gone.** The first version graded confidence in
  four tiers by distance to the nearest station. Tested against actual per-fold error it
  is **unsupported**: r = 0.149, p = 0.33, n = 42. Replaced by the conformal interval.
  Distance still gates *scope* (`max_station_distance_km`, plus a
  `beyond_largest_validated_gap` flag at 10.6 km — the network's own maximum
  nearest-neighbour distance) because no correlation across the 0.67–10.6 km the network
  spans does not license unlimited extrapolation. But it ships as *provenance*, never as
  confidence, and the UI says so.
- **90% is the served coverage level** (Muhammed). 80% and 95% stay calibrated in the JSON.
- **Conformal rather than a Gaussian ±1.645·RMSE**: the residuals are heavy-tailed (signed
  skew 1.22, kurtosis 17.16), so a Gaussian interval is too wide in the middle and too
  narrow in the tail — for air quality the tail is the worse failure. Conformal counts
  percentiles, so distribution shape does not matter.
- **Normalized rather than a fixed ± width**: error here is multiplicative. The 90% width
  as a fraction of the prediction is near-constant across prediction quintiles while the
  absolute width spans roughly ±21 to ±115 µg/m³.
- **Citation is sufficient; no licence file.** Two things were being conflated —
  *attribution* is what we owe upstream (Copernicus/ESA/NASA/OSM; a credit line satisfies
  it), a *licence* is permission we grant downstream (optional, and one sentence covers it
  for an academic project). Muhammed's line, now in the README and every download bundle:
  free for research and educational use with attribution, cite `Muhammed Fiyas, "Delhi
  PM2.5 satellite-ground calibration", 2026`.
- **Three download products with distinct identities** (Muhammed's own specification):
  stations (measured + features, feature selection), 1 km grid (features + estimates at
  native resolution, feature selection), coarser grids (estimates only, aggregated, **no
  features**). All carry the interval and distance to nearest station.
- **No features at coarse resolution.** LightGBM is nonlinear, so `mean(f(x)) ≠ f(mean(x))`
  — the same Jensen's-inequality issue behind the LME's Duan smearing work. Shipping
  coarse features beside coarse predictions would mean a researcher re-running the model
  on the supplied features could not reproduce the supplied prediction. Not shipping them
  makes that impossible to get wrong. Aggregation is always of *predictions*, never of
  features.
- **AOD provenance columns are not deselectable** in the station download. Coupling nearly
  halves on gap-filled rows (0.516 observed vs 0.296 filled, network-wide), so a user who
  could drop the provenance would hold a column whose meaning silently changes between
  rows.
- **ZIP is the default download format** so data cannot travel without its dictionary and
  attribution — a CSV separated from its provenance is the real failure mode.

## Things I got wrong today, and the corrections

- **Claimed LightGBM degrades systematically with buffer exclusions.** The apparent
  gradient was an artifact of 2 stations; removing them reverses it. Fisher p = 0.077.
  Withdrawn.
- **Compared the LME's log-scale R² (0.423) against LightGBM's raw-scale R² (0.803).**
  Different quantities — R² is not invariant under a nonlinear transform. The repo already
  has a convention against exactly this.
- **Suggested better static land-use features would help.** Muhammed pushed back ("will
  this improve the prediction, I don't think so") and was right: static features are
  constant within a station and so cannot by construction explain within-station
  variation, which is what was failing.
- **Mis-stated `±1.645 × 33.7 = ±55`** by mixing the all-42 RMSE with a 12-station sample;
  correct is 41.4 → ±68. And wrote 0.22× for 5 km aggregation when it is 0.27× (applied
  the correlation adjustment in the wrong direction).
- **Labelling bug in my own calibration script**: computed skew/kurtosis on *absolute*
  residuals while describing them against a normal distribution. `|residual|` is
  right-skewed by construction. Fixed to use signed residuals.
- **A coupling-stratification plan was falsified before being built** — spatial
  interpolation of coupling scored r = −0.183 (p = 0.25), and stratum assignment was 57%
  accurate against 67% for a constant guess. Not built; written up in the task log as a
  rejected approach rather than quietly dropped.

## Data notes & gotchas

- **`aod_gap_filled` has three meanings, not two** — found while writing the data
  dictionary, and it would have shipped a wrong definition to users. The flag means "not a
  MAIAC retrieval", not "a value was imputed": `flag=0` is a MAIAC retrieval (6,985 rows,
  51.4%), `flag=1` with non-null `aod_055` is MERRA-2 calibrated (6,509, 47.9%), and
  `flag=1` with **null** `aod_055` means neither was available (101 rows, 0.7%, all in
  monsoon). Those come from `05_apply_gapfill.py`'s `unfillable` branch, which sets
  `gap_filled=1` while leaving the value `None`; they stay in the modelling dataset
  because LightGBM splits on missing natively. `aod_055` is the only column in the dataset
  with nulls. Anything filtering on the flag alone is wrong.
- **`confidence_rmse` is in AOD units, not µg/m³** — it is the RMSE of the per-station
  per-season MAIAC~MERRA-2 regression that produced a fill (range 0.134–0.464), so it
  describes error in the AOD fill, not in the PM2.5 estimate.
- **`season` is both a model feature and a download identifier**, so it must be excluded
  from the selectable feature list or it lands in the frame twice.
- **Conformal guarantees marginal, not conditional coverage.** Pooled held-out coverage is
  89.9%, but per station it ranges 67.4% (Sector-125 Noida) to 98.2%, with 15 of 42
  stations below target. The under-covered stations are those where column AOD tracks
  surface PM2.5 weakly — a property that cannot be computed for an unmonitored location.
  Fixing it would need q = 1.049 (±105%), nearly doubling every interval. Documented in
  the API, the UI and every download bundle rather than papered over.
- **Aggregated intervals genuinely tighten, which was a surprise.** Same-day
  between-station residual correlation is near zero at every distance (0.084 within 2 km,
  0.032 overall) — neighbouring cells do *not* share errors through a common AOD pixel or
  ERA5 cell as expected. So an N-cell mean shrinks the interval by `sqrt((1+(N−1)ρ)/N)`:
  0.52× at 2 km, 0.27× at 5 km. **Valid for the areal mean only**, never for a point
  inside it. ρ currently rests on 16 stations with only 8 close pairs — re-measure on all
  42 folds in step 8.
- A long-running dev server cannot be held open across turns from a Claude Code background
  task; restart it per verification round.
