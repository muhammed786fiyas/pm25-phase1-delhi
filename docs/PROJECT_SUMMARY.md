# Delhi PM2.5 Satellite-Ground Calibration — Project Summary

A reference for presenting this project and answering questions about it. Every
number here was read from the committed outputs in `reports/`, not from memory.

Organised by **what someone is likely to ask**, not by what happened when. For the
chronological record see `docs/logs/tasks/` and `docs/logs/daily/`.

---

## 1. The one-paragraph version

> I built a model that estimates daily PM2.5 anywhere in Delhi from satellite and
> meteorological data, calibrated against 42 ground monitors. It reaches **R² = 0.80**
> under spatial cross-validation — holding out whole stations, which is the honest test
> for a model meant to predict where no monitor exists. I then turned it into a 1 km
> gridded product covering 2,388 cells across a year, with calibrated uncertainty
> intervals and explicit flags marking where the model is extrapolating beyond its
> training data. The whole pipeline is reproducible end to end through DVC.

**If they ask for one number:** R² = 0.8018, RMSE = 33.84 µg/m³, spatial leave-one-station-out.

**If they ask what's distinctive:** I validated spatially rather than randomly, and
quantified what the difference costs — random CV would have reported 0.8830, inflating
the result by 0.08 R². And I tested two intuitive ideas (a distance-based confidence
score, and widening intervals in extrapolation regions) and **removed both** when the
data didn't support them.

---

## 2. The problem

Ground monitors measure PM2.5 accurately but only at points. Delhi has 42 usable
monitors for ~1,500 km² — so for most of the city, and for any location-specific
health or exposure study, there's no measurement.

Satellites see aerosol everywhere but measure **Aerosol Optical Depth (AOD)** — a
column-integrated optical property, not a surface mass concentration. The relationship
between the two varies with humidity, boundary layer height, aerosol composition and
season.

**The task:** learn that relationship from the places where both exist (monitor
locations), then apply it where only satellite data exists.

**Scope:** Delhi, 2025-03-01 to 2026-02-28, retrospective. Not a nowcasting service —
ERA5 reanalysis has ~5-day latency and MAIAC AOD 1–3 days, so the inputs physically
cannot answer "what is PM2.5 right now".

Dropped by rule, not by hand: 5 ended before the window, 1 started after, 2 had no

dependency where the download filtered on a status that depended on the download.

## 4. Features — 23 of them

| Group | Features | Source |
|---|---|---|
| Aerosol | `aod_055`, `aod_gap_filled`, `confidence_rmse` | MAIAC + MERRA-2 |
| Meteorology | temperature, relative humidity, wind speed | ERA5-Land |
| | boundary layer height | ERA5 |
| Vegetation | `ndvi_mean`, `ndvi_gap_filled` | Sentinel-2 |
| Land cover | 8 WorldCover percentages | ESA |
| Terrain | elevation, slope | SRTM |
| Built environment | road density, industrial fraction, distance to power plant | OSM |
| Temporal | season | derived from date |

**All spatial covariates are computed in a 1 km buffer** around the point, matching
MAIAC's native grid. That choice is why 1 km is the only resolution at which the
features mean what the model was trained on.

### Feature importance (by gain)

| Feature | Gain share |
|---|---|
| season | 33.6% |
| temperature | 16.3% |
| aod_055 | 10.5% |
| boundary layer height | 10.1% |
| relative humidity | 9.6% |
| wind speed | 7.6% |
| *(remaining 17 features)* | *12.3%* |

The top six are **season plus four meteorological variables plus AOD** — 87.7% of
total gain between them. That ordering is the honest shape of the problem: *when* and
*under what weather* dominates *where*.

**All 13 static land-use features together carry only 7.8% of total gain.** This
matters for a question that comes up: *"why not add more land-use features?"* — they're
constant within a station, so they cannot by construction explain within-station
variation over time, which is the harder part of the problem.

### The AOD gap-fill

MAIAC retrieves AOD only under clear skies. **48.6% of station-days have no retrieval**,
and the monsoon is nearly total cloud. Those are filled by regressing each station's
MAIAC on MERRA-2 (per station, per season) and predicting.

`aod_gap_filled` has **three** meanings, not two — this trips people up:

| Flag | `aod_055` | Meaning | Share |
|---|---|---|---|
| 0 | present | MAIAC retrieval | 51.4% |
| 1 | present | MERRA-2 calibrated | 47.9% |
| 1 | **null** | neither available | 0.7% |

The flag means "not a MAIAC retrieval", not "a value was imputed". **AOD–PM2.5 coupling
is roughly half as strong on filled rows** (network median r = 0.296) as on retrieved
ones (r = 0.516), so the distinction is substantive, not bookkeeping.

## 5. Modelling

### Two models, deliberately

**Linear mixed-effects model (LME)** as the interpretable baseline — a random intercept
per station, AOD × season interaction, with valid p-values on the coefficients.

**LightGBM** as the predictive model — gradient-boosted trees, no distributional
assumptions, handles missing values natively (which matters: `aod_055` is null on 101
rows and LightGBM splits on missing rather than requiring imputation).

### Results, spatial LOSO, raw µg/m³

| | LME (raw-fit) | **LightGBM** |
|---|---|---|
| R² | 0.4364 | **0.8018** |
| RMSE µg/m³ | 57.15 | **33.84** |

**LightGBM reduces RMSE by 41%.** Per station it wins on 40 of 42 folds.

### Why both are reported in raw µg/m³

The LME is naturally fitted on log(PM2.5) — the residual variance ratio across fitted
quintiles is 1.77× on the log scale against 12.79× on raw, so log is the right scale to
*fit* on. But **R² is not invariant under a nonlinear transform**: a log-scale R² and a
raw-scale R² are different quantities and cannot be tabled against each other.

So the LME is fitted twice — log for the coefficient table (the only valid p-values),
raw as the like-for-like comparator. The log-fit model scored on raw µg/m³ gives
**R² = −0.226**, which shows how much the back-transform costs and why the comparison
had to be done carefully.

*(Duan's smearing estimator corrects the back-transform bias — the naive `exp()` runs
low by ~13% through Jensen's inequality, smearing factor 1.132. Worth knowing: the
correction made spatial-LOSO RMSE slightly **worse** in 4 of 5 variants. It removes bias
in the mean, which is not the same as reducing error on genuinely unseen stations. The
corrected figure is still the right one to report; the naive one is optimistic in a way
that happens to look better.)*

## 6. Validation — the methodological core

### Spatial leave-one-station-out, with a 2 km buffer

Each station is held out in turn **and so is every other station within 2 km**, then
predicted by a model that never saw any of them.

**Why the buffer:** two monitors 1 km apart may share a MAIAC pixel and near-identical
meteorology. Holding out one while training on its neighbour is close to training on
the test point. 12 of 42 stations have at least one neighbour within 2 km (up to 2).

### What random CV would have told me

| | Spatial LOSO | Random CV | Inflation |
|---|---|---|---|
| R² | **0.8018** | 0.8830 | +0.081 |
| within-R² | 0.7156 | 0.7762 | +0.061 |
| RMSE | 33.84 | 26.00 | −7.8 |

Random CV splits rows, so a station's other days leak information about it. **The
honest number is 0.8018.** I report both precisely because the gap is the point —
published satellite-PM2.5 R² values are often random-CV numbers and aren't comparable
to this.

### Block-nested hyperparameter tuning

42 stations were partitioned into 6 blocks of 7 (from connected components of the 2 km
buffer graph, so clusters stay intact). Each block's hyperparameters come from an
Optuna search that block was **held out of**. This prevents the test station influencing
its own hyperparameters.

### Per-fold spread

Median fold R² = 0.854, range −0.125 to 0.963. **38 of 42 stations exceed R² 0.5.**
Two folds are negative.

### Why those two fail — tested, not guessed

Hypothesis: stations where column AOD tracks surface PM2.5 weakly are predicted badly.

Measured coupling as the within-station correlation of `aod_055` and `pm25_daily`
**from observed data only**, so the metric is independent of model output. Correlation
with fold R²: **r = 0.600, p = 2.7e-05**.

Then the important part — the hypothesis was generated by looking at 3 stations, so I
re-tested on the **other 39**: r = 0.335, p = 0.037. It survives out-of-sample, so it
isn't merely a description of the stations that suggested it.

**But state the weakness with it.** On those 39, Spearman is only marginal
(rho = 0.286, p = 0.078), so the result leans on the linear form. It is stronger on
within-R² — the part of the problem that is actually about tracking day-to-day
variation — where all 42 give r = 0.720 (p = 7.5e-08) and the held-out 39 give
r = 0.486 (p = 0.0017). The honest summary: **well supported for within-station skill,
suggestive for overall R².**

## 7. Uncertainty

### Conformal prediction intervals

`interval = prediction × (1 ± q)`, with q a percentile of the relative absolute residual
measured on out-of-fold predictions.

| Level | q | Width | Held-out coverage |
|---|---|---|---|
| 80% | 0.4070 | ±40.7% | 79.97% |
| **90%** | **0.5497** | **±55.0%** | **89.91%** |
| 95% | 0.6896 | ±69.0% | 94.95% |

Calibrated on 13,595 out-of-fold rows and validated by leave-one-station-out: calibrate
q on 41 stations, measure coverage on the 42nd.

### Three design choices, each with a reason

**Multiplicative, not fixed-width** — the error is multiplicative. The relative width is
near-constant across prediction quintiles while the absolute width spans ±21 to ±115 µg/m³.

**Conformal, not Gaussian ±1.645×RMSE** — the signed residuals have **kurtosis 17.6**
(0 would be normal). A Gaussian interval is far too wide mid-distribution and too narrow
in the tail, which for air quality is the worse failure. Conformal counts percentiles, so
distribution shape is irrelevant.

**Symmetric, not asymmetric** — the centring check passes: signed error by prediction
band stays within ±7.9% of level, and the 90% interval misses 5.0% below and 5.0% above.

### The limitation to state before you're asked

**Conformal guarantees marginal coverage, not conditional.** Right on average across all
predictions, *not* at every location.

Per station, held-out coverage ranges **72.0% to 99.1%**, with **18 of 42 below the 90%
target**. The worst is station 5598. Fixing it would need q = 1.049 (±105%), nearly
doubling every interval.

### What I tested and removed

The app originally graded confidence by **distance to the nearest monitor** — intuitive,
and most people would accept it. Tested against actual per-fold error: **r = 0.149,
p = 0.33, n = 42.** No relationship. Removed.

Distance still gates *scope* — nothing is served beyond 15 km from a monitor, because no
correlation across the 0.67–10.6 km the network spans doesn't license unlimited
extrapolation. But it's reported as provenance, never as confidence.

## 8. The prediction product

### 1 km grid

2,388 cells (of 2,600 in the bounding box; 212 dropped beyond the 15 km coverage radius)
× 365 days = **871,620 predictions**, each with a 90% interval and an extrapolation flag.

Predicted range 12.9–440.3 µg/m³, mean 86.7 — against the stations' observed mean of 86.9.

Seasonal pattern, which is the first sanity check anyone will apply:

| Season | Mean µg/m³ |
|---|---|
| Monsoon | 37.9 |
| Summer | 66.8 |
| Winter | 137.3 |
| Post-monsoon | 139.5 |

### How the grid was validated — with no ground truth

Grid cells have no measurements, so the only end-to-end test is: **does the cell
containing a station predict what the station predicts?**

| | |
|---|---|
| correlation | **0.9901** |
| mean difference | −0.228 µg/m³ |
| median difference | **−0.110 µg/m³** |
| median \|difference\| | 2.678 µg/m³ (4.05%) |

Across 13,595 station-days. **The near-zero bias is the informative part** — a mis-joined
feature, a wrong scale or a shifted date would show as a systematic offset. The residual
scatter is expected: cell centres sit up to 640 m from their station and every covariate
is a 1 km-buffer statistic, so the two genuinely describe different ground.

### Aggregation to 2/5/10 km

Coarser products are **areal means of the 1 km cells**. Their intervals shrink, by a
measured amount:

| Grid | Cells averaged | Shrinkage | Interval |
|---|---|---|---|
| 1 km | 1 | 1.000 | ±55.0% |
| 2 km | 4 | 0.536 | ±29.5% |
| 5 km | 25 | 0.297 | ±16.3% |
| 10 km | 100 | 0.244 | ±13.4% |

Shrinkage = `√((1 + (N−1)ρ) / N)` where **ρ = 0.050** (bootstrap 95% CI [0.022, 0.085])
is the same-day correlation between two locations' prediction errors, measured across
all 861 station pairs.

**Two findings worth telling:**

**ρ doesn't decay with distance** (slope p = 0.62). Stations 1 km and 40 km apart share
the same error correlation — so it's a *whole-day* effect, not a local one. On
2025-05-22, 35 of 38 stations erred in the same direction by a mean of −29%, against 60%
/ −3% on a typical day. Something regional the model can't see.

**That implies a floor.** A shared error can't be averaged away, so shrinkage tends to
√ρ = 0.224, not zero. 10 km already sits at 0.244 — **aggregating beyond ~5 km buys
almost no precision.** Offer it for file size, not accuracy.

### The trap in the coarse products

A 5 km interval of ±16% looks like better data than 1 km's ±55%. **It isn't.** It
describes the *average over 25 km²*.

A real 5 km cell on 2025-12-15 reports 282.9 µg/m³ with an interval of 237–329. Its 25
constituent 1 km cells range from **201 to 327** — the lowest falls outside the coarse
interval entirely.

For a point question, the honest answer is the 1 km value and its wider interval. This
warning ships in `ATTRIBUTION.txt` of every coarse download, in the API response, and in
the UI.

### Three download products

| Product | Features | Why |
|---|---|---|
| Stations | ✓ selectable | The only product with measured values |
| 1 km grid | ✓ selectable | **Reproducible** — verified: re-running the model on the shipped features reproduces every prediction to within 0.005 µg/m³ |
| 2/5/10 km | **none** | Nonlinearity means averaged features can't reproduce averaged predictions — omitting them makes the error impossible rather than merely documented |

## 9. Design decisions, with the alternative rejected

| Decision | Alternative rejected | Why |
|---|---|---|
| Spatial LOSO with 2 km buffer | Random CV | Random CV inflates R² by 0.081 through station leakage |
| Block-nested tuning | One global search | A station would influence its own hyperparameters |
| Report both models in raw µg/m³ | Compare log-R² to raw-R² | R² isn't invariant under nonlinear transform — different quantities |
| Conformal intervals | Gaussian ±1.645×RMSE | Residual kurtosis 17.6; Gaussian misfits both middle and tail |
| Multiplicative interval | Fixed ± width | Relative error is stable, absolute spans ±21 to ±115 |
| Distance = provenance | Distance = confidence | Tested against error: r = 0.149, p = 0.33 |
| Flag extrapolation, don't widen | Widen intervals out of range | Tested; no measured relationship (§10) |
| Aggregate predictions | Aggregate features | `mean(f(x)) ≠ f(mean(x))` — Jensen's inequality |
| No features at coarse resolution | Ship them with a caveat | A reproduction attempt would fail; omission prevents it |
| 1 km native grid | 5 km to save compute | 5 km sampling isn't a 5 km areal mean, and 1 km is MAIAC's native grid |
| Keep re-tuned R² 0.8018 | Revert to 0.8035 | Picking hyperparameters by test score reintroduces leakage |
| Prediction-only OSM extract | Extend the training export | Training has no gap; extending would dirty it for no benefit |
| Per-cell gap-fill calibration | Borrow nearest station's | The method *is* calibrate-where-you-fill |

## 10. Problems found, and how

*(Useful for "tell me about a mistake you found". Skip when presenting.)*

### A double-counting bug in a trained-on feature

`04_extract_industrial_area.py` summed each clipped polygon's area independently. OSM
sometimes maps the same industrial land twice — near station 5627 the estate "Okhla Ph
III" appears as two identical 418,465 m² polygons — so shared land was counted twice.

It inflated `industrial_landuse_fraction` at **5 of 42 stations**: 5627 held 0.4481
against a true 0.3147 (+42%), 6960 held 0.1167 against 0.0698 (+67%).

**Why it survived QC for months, and the lesson:** the QC gate hard-fails when a
*fraction exceeds 1*. With 42 stations none ever did. The 2,388-cell grid is 57× the
sample and produced a cell at 1.06, tripping it immediately.

> **A QC threshold that has never fired is not evidence that it never will.**

Fixed with `union_all()`. The full chain re-ran including a fresh Optuna search; R² moved
0.8031 → 0.8018.

### A silently incomplete data source

Building the prediction OSM extract, I used Geofabrik's "India Northern Zone". It
**excludes Uttar Pradesh**. The extract held 112 power plants against the training
export's 170 — every one of the 57 east of longitude 77.36 was missing, including Dadri
— and only 76% of training's roads in the 77.30–77.36 strip, which is Noida and
Ghaziabad, *inside* the study area.

Both would have produced *plausible wrong numbers with no error anywhere*: eastern cells
would simply have reported a more distant power plant and less road. Caught only by
diffing against the training export rather than eyeballing the new files.

### Testing an intuition and finding nothing

585 cells are materially outside the training range. The intuitive fix is to widen their
intervals. Before doing that, I tested whether being unusual actually predicts worse
coverage, using the 42 stations' measured held-out coverage.

| Check | Result |
|---|---|
| Pearson | r = −0.415, **p = 0.0063** ✓ |
| Spearman | r = −0.060, p = 0.708 ✗ |
| Drop most extreme station | **r = +0.098**, p = 0.541 ✗ sign reverses |
| Median split | difference −0.006, p = 0.78 ✗ |

The significant Pearson is produced **entirely by one station** — 5598, sitting 102
range-widths beyond every other on `wetland_herbaceous_pct`. Drop it and the correlation
reverses sign. Splitting the 42 at the median unusualness gives 89.6% coverage on the
more unusual half against 90.2% on the less unusual half — a 0.6 point difference,
p = 0.78.

**Conclusion: no relationship.** Any widening factor would have been invented, and an
invented correction that looks rigorous is worse than an honest flag.

## 11. Limitations — state these before you're challenged

1. **Conformal coverage is marginal, not conditional.** 72.0%–99.1% per station, 18 of
   42 below target.
2. **585 of 2,388 cells (25%) are materially outside the training range**, 93 beyond any
   information the model has. Every CPCB monitor is urban, so rural cells are
   extrapolation *by construction* — `road_density` and `built_up_pct` have training
   minima well above zero.
3. **LightGBM cannot extrapolate.** It returns the boundary prediction, which looks like
   a normal answer.
4. **ρ's close-pair sample can't be improved** — 8 pairs under 2 km is all Delhi's network
   offers; more folds don't help.
5. **Retrospective only.** ERA5 ~5-day latency, MAIAC 1–3 days.
6. **48.6% of AOD is gap-filled**, and coupling is roughly half as strong on those rows.
7. **One city, one year.** Nothing here establishes transferability.
8. **Unverified:** CPCB/OpenAQ redistribution terms, and whether OSM-derived columns are
   an ODbL "Produced Work" or "Derivative Database".

## 12. Likely questions, with answers

**"Is R² = 0.80 good?"**
For spatial LOSO, yes. The comparable figure matters more than the absolute: the LME
baseline gets 0.44 on identical folds, and random CV on the same model gives 0.88 —
which is roughly what published satellite-PM2.5 papers report, because many use random
splits. Against the honest benchmark it's strong; against the inflated one it's ordinary.

**"Why LightGBM over deep learning?"**
13,595 training rows and 23 features. A neural network has nothing to exploit at that
scale and would be harder to validate honestly. Trees also handle missing AOD natively,
which matters when 0.7% of rows have none.

**"How do you know the grid is right when there's no ground truth?"**
The cell containing a station must predict what the station predicts — correlation
0.9901, median difference −0.11 µg/m³. The near-zero *bias* is the test; a broken join
would show as an offset.

**"Why not use distance to the nearest monitor as a confidence measure?"**
I did, initially. Then I tested it against actual per-fold error: r = 0.149, p = 0.33.
No relationship, so I removed it rather than keep something plausible-sounding.

**"Your coarse products have tighter intervals — isn't that better data?"**
No, it's a different quantity. The ±16% at 5 km describes the average over 25 km². One
real cell reads 282.9 while the 1 km cells inside it span 201–327.

**"What would you do with more time?"**
Wind direction — ERA5's u/v components are already extracted but collapsed to wind
speed, and direction is one of the few *time-varying* signals not yet used. More static
land-use features wouldn't help: they're constant within a station, so they can't explain
within-station variation, and all 13 together carry 7.8% of gain.

**"What's the weakest part?"**
The conditional coverage gap. The interval is honest on average but can be as low as 72%
at a single station, and the stations where it fails are the weakly-AOD-coupled ones —
a property I can't compute for an unmonitored cell, which is exactly where I'd need it.

**"How reproducible is it?"**
128 DVC stages, end to end from raw downloads. External fetches are frozen so re-runs
use pinned snapshots — OpenAQ and GEE both revise historical data. Hyperparameter
tuning is seeded, so a fresh clone reproduces R² = 0.8018 exactly.

## 14. Where things live

```
scripts/datasets/      per-source extraction (CPCB, MAIAC, MERRA-2, ERA5, GEE, OSM)
scripts/modeling/      dataset prep, LME, LightGBM
scripts/prediction/    grid build, grid features, inference, aggregation
app/                   FastAPI service + map UI + About page
data/training/         features and targets for the 42 stations
data/prediction/       the 1 km grid and everything derived from it
reports/               all metrics, diagnostics and calibration outputs
docs/logs/tasks/       per-module detail
docs/logs/daily/       chronological record
```

**Key principle in the layout:** the same extractor scripts compute both training and
prediction features. They are never duplicated, because the model was fitted on what
those scripts produce — a second copy would drift and silently feed the model a
different quantity.
